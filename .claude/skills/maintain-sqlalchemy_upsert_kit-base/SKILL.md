sqlalchemy_upsert_kit does one thing: three bulk upsert strategies (insert or ignore, insert or replace, insert or merge), each staged through a temporary table, on several database backends. Everything that is the same on every database lives in `sqlalchemy_upsert_kit/core/`: input validation, the staging table, and the workflow (`UpsertExecutor`), which runs each call inside one SAVEPOINT. Each backend is its own subpackage, `sqlalchemy_upsert_kit/<engine>/` (today `sqlite/`, `postgres/` and `mysql/`), exposed as `api.<engine>`: its executor overrides only the hooks its database needs (the upsert statement always; how a transaction begins, how the staging table is dropped and cleaned up, how rows are counted, the identifier limit, and checks of other unique keys before and after the upsert, where the database differs), and its three modules hold the public functions. One shared contract suite, `sqlalchemy_upsert_kit/tests/contract.py`, tests every backend the same way.

For template conventions (layout, code style, tests, docs, release), load `pywf-oss-base`. This family records only what is specific to this library.
