sqlalchemy_upsert_kit does one thing: three bulk upsert strategies (insert or ignore, insert or replace, insert or merge), each staged through a temporary table, on several database backends. The dialect-agnostic workflow (transaction modes, staging table lifecycle, failure cleanup, test failure injection) is `sqlalchemy_upsert_kit/core/executor.py`. Each backend is its own subpackage, `sqlalchemy_upsert_kit/<engine>/` (today `sqlite/` and `postgres/`), which subclasses the core executor and holds all of its own SQL, and is exposed as `api.<engine>`.

For template conventions (layout, code style, tests, docs, release), load `pywf-oss-base`. This family records only what is specific to this library.
